# RALLY｜集结：市场／行业调研

> 研究对象不是“工厂智能工牌”，也不是一款以硬件销售为核心的产品，而是一个独立运行的 To C 手机产品：用户授权展示自己的状态、能力和项目证据，AI 辅助匹配人／项目／团队缺口，线下可通过 NFC 卡片发起建联，双方确认后组队并启动协作。实体卡片只是跨手机生态的可选入口和线下获客媒介。

## 研究摘要

- **Fact：需求不是凭空创造。** Devpost、TAIKAI 已经提供黑客松组队能力，YC Co-Founder Matching、CoffeeSpace 提供合作伙伴匹配，Grip、Brella 提供活动现场 AI networking，Klik、Mobilo 等提供 NFC 建联。这些相邻产品共同证明“找人、确认关系、现场交换身份”分别存在需求。[Devpost](https://help.devpost.com/article/75-participants-page-forming-a-team)｜[TAIKAI](https://taikai.network/)｜[YC Co-Founder Matching](https://www.ycombinator.com/cofounder-matching)｜[Grip](https://www.grip.events/)｜[Bizzabo Klik](https://www.bizzabo.com/event-management-software/klik-smart-event-badges)
- **Inference：真正可能成立的产品空白**不是“AI 找人”或“NFC 名片”，而是把**授权展示—AI 匹配—线下触碰—双方确认—团队启动—协作证据沉淀**连成一个面向个人的闭环。
- **Fact：当前主流付费者不是个人。** 活动 networking、智能胸牌和数字名片厂商主要面向主办方、销售团队、CRM 与企业客户；YC 的个人匹配功能免费，CoffeeSpace 也把创始人／人才侧设为免费。[YC](https://www.ycombinator.com/cofounder-matching)｜[CoffeeSpace](https://www.coffeespace.com/)｜[Grip](https://www.grip.events/)｜[Mobilo](https://www.mobilocard.com/)
- **Inference：黑客松适合做高密度冷启动，不足以单独支撑长期留存。** 用户的“找队友”需求在赛前和开赛初期很强，但天然低频；赛后若不能继续承接开源项目、创业项目、比赛、共创和职业协作，产品会退化为一次性活动工具。
- **Inference：96 小时做出有说服力的 Demo 可行，做成独立 To C 生意仍属中高风险。** 技术难点低于网络密度、身份真实性、赛后留存和付费意愿。NFC 能增强仪式感和传播，但不能替代产品本身，也不是壁垒。

### 当前判断卡

| 维度 | 判断 | 依据 |
|---|---:|---|
| 黑客松现场痛点 | 较强 | 多个平台持续提供找队友、讨论区、聊天和邀请能力 |
| 96 小时 Demo 可实现性 | 高 | H5／App、资料结构化、匹配解释、NFC URL 与双方确认均可用成熟技术实现 |
| 相对现状的差异化 | 中 | 完整闭环有差异，但每个单点都已有替代方案 |
| 黑客松场景分发效率 | 较高 | 人群集中、身份明确、时间压力强，适合现场裂变 |
| 赛后自然留存 | 偏低 | 黑客松低频，需要跨活动的持续协作场景承接 |
| 纯 To C 付费证据 | 弱 | 已观察到的相邻个人匹配产品多为免费，行业收入更多来自 B 端 |
| 当前产品壁垒 | 低 | NFC、AI 标签和滑动匹配均易复制 |
| 数据网络形成后的潜在壁垒 | 中高 | 真实协作关系、项目结果、互评和匹配反馈可形成专有数据飞轮 |

> 上表除明确引用的行业事实外均为本研究的 **Inference**，用于决策而不是作为已验证市场数据。

## 1. Scope

**Market / problem space：** 线下高密度创新活动中的个人能力展示、人才发现、团队形成、即时建联和协作启动。  
**Boundary：** 首发为中国黑客松参赛者；长期可延伸至 Game Jam、创客活动、开源社区、AI 共创营、创业周末和项目制自由协作。  
**Decision supported：** 判断该方向是否适合作为 96 小时黑客松项目及赛后独立 To C 产品，并确定最小切入口、商业化假设和验证顺序。  
**As-of date：** 2026-08-28。

### 1.1 证据口径

- **Fact：** 可被官方页面、技术文档或论文核验的事实；商业数字均保留“厂商自报”属性。
- **Inference：** 基于多个事实形成的产品或市场判断，仍需真实用户行为验证。
- **Assumption：** 为推进方案暂时采用、尚无充分证据的假设。
- **Gap：** 本轮没有找到可信、可比的“黑客松组队 To C 市场规模”数据，因此不引用泛化的社交 App、活动科技或 NFC 市场报告冒充本项目 TAM。

### 1.2 本次不研究的边界

- 不把原有非标工厂／一线协同方案混入本项目市场判断；
- 不把 NFC 卡片销量等同于软件需求；
- 不用 GitHub 开发者总数直接计算可付费用户；
- 不把主办方管理后台、招聘 ATS 或企业 CRM 作为首版核心产品；
- 不把“市面上尚无完整同类产品”直接解释为存在市场机会。

## 2. How This Market Segments

用户今天不是从一个完整品类中选购产品，而是把以下五类工具拼起来完成任务。

1. **合作伙伴／人才匹配：** 用户创建资料、浏览或接受算法推荐，双方同意后建立联系。代表产品为 YC Co-Founder Matching、CoffeeSpace。
2. **黑客松组队与赛事平台：** 用户找队友、创建或加入团队、聊天、提交项目；主办方管理赛事。代表产品为 Devpost、TAIKAI、MLH 生态。
3. **活动现场 networking：** 依据目标、兴趣和身份推荐参会者，安排会面并记录线索。代表产品为 Grip、Brella。
4. **NFC 数字身份与智能胸牌：** 通过卡片、徽章或可穿戴设备打开资料页、交换联系方式、采集现场触点。代表产品为 Bizzabo Klik、Blendology、Mobilo、Popl。
5. **协作与能力证明：** GitHub 承载代码证据，LinkedIn 承载职业身份，微信／Discord 承载沟通，飞书／Notion 承载协作；这些工具不负责一次性完成组队判断。

**Vendor / user disagreement｜Inference：** 厂商按“赛事平台、活动科技、数字名片、职业社交、协作软件”销售，用户真正经历的却是一条连续任务链：**我现在缺什么人—谁值得聊—怎么低摩擦建联—是否愿意组队—如何马上开始—这次协作能否成为下次匹配的可信证据。** 产品机会位于类别之间，而不是某个已有类别内部。

## 3. Player Map

### 3.1 Direct players

- **YC Co-Founder Matching：** 创建个人资料、由匹配引擎推荐候选人、发出邀请并在双方接受后连接；官网称已产生 100,000+ 次匹配，个人免费。它证明高风险合作关系也能从结构化资料和双向确认开始，但场景偏长期创业搭档。[官网](https://www.ycombinator.com/cofounder-matching)
- **CoffeeSpace：** 提供 AI 匹配、滑动交互、项目／执行证据，官网自报 30,000+ 用户、2.5M+ swipes 和 65,000+ matches；创始人和人才免费，企业招聘付费。它最接近“专业协作版 Tinder”的交互与定位。[官网](https://www.coffeespace.com/)
- **Devpost：** 参赛者可标记“looking for teammates”，填写自我介绍、Idea 和所需队友；候选人收到 Team-up request，确认后仍需由队长通过邮件或链接正式加入团队。Devpost 还建议主办方使用 Discord、讨论区和参与者列表补充互动，说明现有组队链路仍然分散。[组队帮助](https://help.devpost.com/article/75-participants-page-forming-a-team)｜[社区与组队](https://help.devpost.com/article/65-community-and-forming-teams-during-online-hackathons)
- **TAIKAI：** 已把参赛者 matchmaking、站内聊天、团队邀请和项目提交放在同一平台中，说明“匹配＋赛事协作”并非无人覆盖。[官网](https://taikai.network/)
- **DoraHacks：** 中国起源、全球运营的 builder 社区和黑客松基础设施，覆盖项目提交、赛事参与、奖金／Grant，以及主办方侧的审核、评审、通信和分析。它是国内场景不能忽略的活动入口；其首页规模数字为动态加载，本轮不引用搜索摘要中的用户量。[官网](https://dorahacks.io/)

### 3.2 Adjacent players (could enter)

- **Grip：** 面向活动提供 AI matchmaking、会议预约、活动 App 和智能胸牌；官网自报服务 5,000+ 场活动、15M+ 参与者和 2M+ meetings。若其强化个人长期身份，容易进入本项目边界。[官网](https://www.grip.events/)
- **Brella：** 按参会意图进行 AI matchmaking，并提供会面和线索采集。其优势是活动侧分发和成熟运营，弱点是关系通常从属于单场活动。[官网](https://www.brella.io/)
- **Bizzabo Klik：** 以可穿戴胸牌实现 click-to-connect、联系方式交换、内容触点和活动分析，证明实体交互能在活动现场成立；但商业价值中心是主办方数据和线索。[官网](https://www.bizzabo.com/event-management-software/klik-smart-event-badges)
- **Mobilo：** NFC 数字名片支持接收方无需安装 App，并以 QR 作为兼容备份；当前商业重点是企业名片、CRM 和线索管理。它能快速复制“碰一下打开个人页”，但不负责判断是否适合组队。[官网](https://www.mobilocard.com/)

### 3.3 Substitutes and non-consumption

- **微信／微信群／Discord：** 大多数人已经安装，交换账号后马上能沟通；缺点是能力信息、团队缺口和关系来源不可结构化。
- **GitHub／LinkedIn／个人作品集：** 能提供身份和作品证据，但现场筛选成本高，也不直接表达“我现在是否愿意组队”。
- **二维码／口头自我介绍／现场贴纸：** 成本极低、无需额外硬件；若它们已经足够，NFC 只是更好看的交互，而不是必要产品。

### 3.4 Emerging entrants

- **AI 团队形成研究：** 2026 年已有研究尝试用 AI 支持黑客松团队形成。这是问题受到关注的技术信号，但论文存在不等于付费市场成立。[IEEE DOI](https://doi.org/10.1109/icetems66917.2026.11469266)
- **Gap：** 本轮未找到一个已被可靠验证的独立 To C 产品，同时覆盖“赛前状态展示、AI 组队、线下碰触归因、双向确认、赛后协作身份”。这是条件性空白，不是无竞争市场。

## 4. Dynamics

### 4.1 Where the money is

- **Fact：** Grip、Brella、Klik、Popl、Mobilo 等相邻产品重点销售给活动主办方、企业销售团队或 CRM 使用方；现场连接产生的商业价值主要被解释为会议、线索和活动数据。[Grip](https://www.grip.events/)｜[Brella](https://www.brella.io/)｜[Popl](https://popl.co/pages/digital-business-card)
- **Fact：** YC Co-Founder Matching 对个人免费；CoffeeSpace 的创始人／人才侧免费，企业招聘侧付费。[YC](https://www.ycombinator.com/cofounder-matching)｜[CoffeeSpace](https://www.coffeespace.com/)
- **Inference：** “个人找合作伙伴”需求已被验证，但“个人愿意持续为找合作伙伴付费”尚未被验证。纯 To C 商业化是本项目比技术实现更大的风险。

### 4.2 Where the momentum is

- **Fact：** AI matching 已从创业搭档匹配扩展到活动 networking，推荐依据从静态职位标签走向意图、项目和执行证据。[CoffeeSpace](https://www.coffeespace.com/)｜[Grip](https://www.grip.events/)｜[Brella](https://www.brella.io/)
- **Fact：** GitHub 2025 Octoverse 称平台开发者超过 1.8 亿，2025 年新增超过 3,600 万，并观察到 AI 工具快速进入开发者工作流。这个数字只能说明开发者身份和协作基础设施规模，不能直接视为本产品用户数。[GitHub Octoverse 2025](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)
- **Inference：** AI 降低了从资料中提取能力标签、解释匹配理由和生成启动任务的成本，但也让“AI 匹配”本身迅速商品化。

### 4.3 Consolidation or fragmentation

- **Inference：** 市场高度碎片化：比赛平台掌握活动入口，职业／代码平台掌握身份与证据，活动科技掌握现场关系，协作工具掌握赛后行为。新产品必须用极短链路证明跨工具整合的价值，否则用户会继续使用现有组合。

### 4.4 Technology and behavior shifts

- **Fact：** Apple 支持部分 iPhone 在后台读取 NFC 标签，但标签读取后通常先出现通知，用户点击后才会打开 App 或 Safari；未安装 App 时 Universal Link 可回落到网页。[Apple Core NFC](https://developer.apple.com/documentation/corenfc/adding-support-for-background-tag-reading)
- **Fact：** Android 支持读取包含 URI 的 NDEF 标签并分发到 App 或网页，但具体行为受系统版本、设备状态和默认应用设置影响；Android 16 起 HTTP／HTTPS 标签改由 `ACTION_VIEW` 处理，Android 17 起会显示“打开链接”通知并要求用户明确操作。[Android NFC](https://developer.android.com/develop/connectivity/nfc/nfc)
- **Inference：** NFC 解决的是“跨生态统一入口”和现场仪式感，不是无感通信。产品必须支持通知点击、H5 回落、二维码备用和双方确认。

## 5. Whitespace and Dead Zones

### 5.1 从“认识一个人”到“启动一个团队”

- **Opportunity｜Inference：** 现有工具通常停在推荐、交换联系方式或加入群聊；产品可在双方确认后给出团队能力覆盖、角色建议、风险提示和 3 个启动任务，把社交结果变成协作结果。
- **Dead-zone counter-reading：** 黑客松团队常由朋友、同学或现场临时交流组成；如果 AI 建议没有明显优于五分钟对话，它只增加步骤。
- **验证标准：** 与“自由交流＋微信群”相比，产品能否显著缩短从首次见面到确认团队的时间，并提高双方对角色分工的清晰度。

### 5.2 可归因的线下碰触关系

- **Opportunity｜Inference：** NFC 卡可把线下见面准确归因到某个身份和某次活动，并将接触后行为带回 App，形成可测的获客与关系链路。
- **Dead-zone counter-reading：** QR 码、微信名片和 AirDrop 已足够便宜；NFC 仍可能要求点通知，静态标签还可被复制，因此体验增量可能不足以支撑新硬件。
- **验证标准：** 在同一现场对比 NFC、二维码和直接加微信的发起成功率、完成时间、次日资料补全率和 7 日后有效对话率。

### 5.3 跨活动的 AI 协作身份

- **Opportunity｜Inference：** 把“自我声明的能力”逐步升级为“项目结果、队友互评、实际角色和重复合作”的证据，可改善下一次匹配，并形成难以一次性复制的数据资产。
- **Dead-zone counter-reading：** 用户参加黑客松和临时组队的频率可能过低，也未必愿意公开协作评价；若没有跨活动使用理由，数据飞轮不会启动。
- **验证标准：** 首场活动结束 30 天后，是否仍有用户更新资料、发起新项目、回应匹配或复用原团队关系。

## 6. So What?

### 6.1 对当前决策的三条含义

1. **Inference｜高置信：** 96 小时项目应只演示一条纵向闭环：**授权展示状态 → AI 推荐 → NFC／链接发起 → 双方确认 → 自动生成团队与启动任务**。不需要同时做完整社交网络、赛事后台和复杂硬件。
2. **Inference｜高置信：** 黑客松应被定义为 beachhead（首发楔子）和线下获客渠道，不应被定义为长期市场边界；长期命题是“项目制协作身份与关系网络”。
3. **Inference｜中置信：** 产品可以保持 To C，但收入模型不能只押长期订阅。先用卡片套装和单场活动通行证验证个人付费，再决定是否发展月度会员。

### 6.2 下一步最值得深挖的两个玩家

1. **CoffeeSpace：** 最接近 AI 时代专业匹配／滑动交互，需要重点研究它如何解决冷启动、资料质量和匹配后的结果追踪。[官网](https://www.coffeespace.com/)
2. **TAIKAI／Devpost：** 最接近黑客松真实组队链路，需要验证用户为什么仍然转向 Discord、微信群和线下交流，以及现有组队功能在哪一步流失。[TAIKAI](https://taikai.network/)｜[Devpost](https://help.devpost.com/article/75-participants-page-forming-a-team)

### 6.3 必须验证的三个假设

1. **Assumption：** 未组队者和缺人的团队愿意在活动现场公开“可被发现”状态，并至少展示三项能力证据。
2. **Assumption：** 匹配解释和协作启动建议能比关键词标签明显提高有效对话率，而不只是增加“AI 感”。
3. **Assumption：** 黑客松结束后仍有至少一种月度使用场景，足以让关系、项目和协作评价继续沉淀。

| 希望拓展合作的人 | 已组队但愿意认识人 | 加了好友却不知道为何而加 | 保留见面上下文和未来可合作的理由 |

> 当我身处一个时间有限、陌生人密集的创新活动，并且需要找到队友或合作机会时，帮助我快速知道“谁值得聊、为什么值得聊”，用双方都能控制的方式建立关系，并把这次见面直接转化为可执行的下一步。

**Fact｜研究侧证：** 一篇 2023 年开放获取的黑客松综述指出，技术型黑客松常见困难包括招募具有合适专业背景的参与者；预组队通常协作更顺畅，但也可能降低团队专业多样性。该综述建议团队规模控制在 3–6 人，并尽早公布团队，让成员提前理解彼此优势与不足。这支持“能力互补与早期组队很重要”，但不能证明用户一定会采用 AI Tinder 或 NFC。[Hack your organizational innovation](https://innovation-entrepreneurship.springeropen.com/articles/10.1186/s13731-023-00269-0)

### 7.3 用户最小资料结构

- 当前状态：未组队／有 Idea 找人／团队缺人／已组队但可交流；
- 能力标签：前端、后端、AI、硬件、产品、设计、商业等；
- 能力证据：GitHub、作品链接、演示、比赛或真实项目；
- 想做的主题与不想做的主题；
- 可投入时间和现场位置；
- 协作偏好：快速试错／工程质量／表达展示／商业验证等；
- 用户自主选择的公开范围和到期时间。

**Product principle｜Inference：** “现在是否可被发现”必须是临时、显式、可撤回的授权，而不是默认永久公开。

## 8. 市场规模代理指标与边界

### 8.1 可引用的上层代理指标

- **Fact：** GitHub 官方称 2025 年平台开发者超过 1.8 亿，全年新增超过 3,600 万。[GitHub Octoverse](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)
- **Fact：** GitHub 2024 Octoverse 称中国开发者超过 900 万、同比增长 10%；这说明国内存在足够大的开发者基础，但仍不能等同于愿意参加陌生人组队的目标市场。[GitHub Octoverse 2024](https://github.blog/news-insights/octoverse/octoverse-2024/)
- **Fact：** Devpost 当前官方页面同时出现“600 万+ builders”和“400 万+ developer community”两种口径，官网自身并不一致。这些数字只能视为平台自报的可触达人群，不能当作活跃参赛者或本产品可获客用户。[Public Hackathons](https://info.devpost.com/product/public-hackathons)｜[About](https://info.devpost.com/about)
- **Fact：** MLH 自称全球最大的开发者社区之一，并每年支持数百场活动；可说明黑客松是持续存在的分发网络，但不能据此推导个人付费规模。[MLH About](https://www.mlh.com/about)

### 8.2 为什么暂不输出伪精确 TAM

1. GitHub 账户数包含职业开发者、学生、机器人／重复账户等多种群体；
2. 黑客松参与者与“现场尚需组队者”之间还要经过多层筛选；
3. 单人可能一年参加多场活动，活动人次不能直接视为独立用户；
4. 相邻产品多数免费，用户数不能直接乘一个任意订阅价格；
5. 长期市场取决于产品能否从黑客松扩展到持续的项目协作。

### 8.3 建议采用的 bottom-up 口径

先用真实活动数据计算可服务市场，而不是用行业报告倒推：

```text
单场可服务用户数
= 到场人数
× 愿意公开协作状态的比例
× 有组队／拓展协作需求的比例

单场有效网络规模
= 完成资料且收到至少一次有效推荐的用户数

单场 To C 收入
= NFC 卡片购买人数 × 卡片毛利
+ 单场 Premium 购买人数 × 单场净收入

年度可复用用户
= 首场激活用户
× 30 日仍有项目／匹配行为的比例
```

**Assumption：** 在没有至少 3 场真实活动数据前，不给出全国收入 TAM；现阶段最有决策价值的是单场漏斗、复用率和个人付费率。

## 10. NFC 技术与兼容性边界

### 10.1 可实现的真实链路

```text
用户 A 的被动 NFC 卡
→ 用户 B 手机读取 NDEF URL
→ 系统通知／浏览器／App Link
→ 打开 A 的公开状态页
→ B 登录或轻量授权后发起建联
→ A 在 App 内确认
→ 建立双向关系并保存活动上下文
```

### 10.2 必须写进产品设计的限制

- **Fact：** NFC Forum 的 NDEF 是跨设备和标签的数据格式，URI Record 可承载网页地址。[NFC Forum Specifications](https://nfc-forum.org/build/specifications/)
- **Fact：** iPhone 并不等于“碰一下自动建联”；兼容机型读取后通常仍需用户点击系统通知。[Apple Core NFC](https://developer.apple.com/documentation/corenfc/adding-support-for-background-tag-reading)
- **Fact：** iPhone 锁定时需要先解锁；设备从未解锁、正在进行 Core NFC 会话、使用 Apple Pay／Wallet 或处于飞行模式等情况下，后台读取可能不可用。[Apple Core NFC](https://developer.apple.com/documentation/corenfc/adding-support-for-background-tag-reading)
- **Fact：** Android 的行为会随版本、机型、锁屏状态和设置变化，不能承诺所有设备一致；Android 17 对网页标签也要求用户通过通知明确打开。[Android NFC](https://developer.android.com/develop/connectivity/nfc/nfc)
- **Inference：** 卡内只应保存公开 URL／随机卡片标识，不保存私密个人信息或可直接建立关系的长期凭证。
- **Inference：** 静态 NFC URL 可以被复制；因此触碰只负责“发起请求”，正式建联必须由卡主确认，并保留撤销、拉黑和举报能力。
- **Requirement：** 每张卡同时印 QR 码；未安装 App 的用户先进入 H5，不强制在完成建联前下载 App。

### 10.3 NFC 对产品的正确定位

| 它能解决 | 它不能解决 |
|---|---|
| iOS／Android 之间统一打开一个入口 | 自动判断两个人是否适合合作 |
| 降低现场输入账号和搜索姓名的摩擦 | 完全无感、无确认地建立关系 |
| 提供可传播的实体符号和仪式感 | 形成长期留存与数据壁垒 |
| 将一次线下接触归因到卡片／活动 | 替代隐私授权、身份验证与信任机制 |

## 11. 商业化与裂变增长闭环

### 11.1 商业化原则

产品体验和账户体系可以保持完全 To C；主办方可以成为分发渠道，但 96 小时版本不需要做主办方 SaaS。真正需要验证的是：个人是否愿意为更高效的组队和更强的协作身份付费。

### 11.2 建议的收入验证顺序

1. **实体卡片／徽章套装：** 一次性购买，验证用户是否愿意为身份表达和碰触体验付费；它是收入补充，不是高壁垒业务。
2. **单场 Premium Pass：** 按一次活动收费，提供高级筛选、更多主动邀请、团队缺口分析、AI 破冰和协作启动包；比一开始要求月度订阅更符合低频场景。
3. **长期个人会员：** 只有在用户跨活动使用成立后，再提供项目雷达、持续匹配、协作档案、深度匹配解释和复盘助手。
4. **远期可选项：** 人才推荐、项目交易或服务撮合会改变产品边界和激励机制，不应作为首版商业闭环。

> **Assumption：** 上述付费项没有现成证据，价格也不应在调研阶段拍脑袋确定。建议先用预售、假门测试或单场购买按钮测试真实意愿。

### 11.3 裂变增长链路

```text
用户在活动前创建资料并授权状态
→ 现场展示卡片／身份页
→ 另一位参与者触碰或扫码
→ H5 查看“为什么值得认识”
→ 发起请求并完成双方确认
→ 新用户为了回复而补全资料
→ 新用户也获得可展示、可触碰的身份
→ 活动内可匹配节点增加
```

**Inference：** 这条链路只有在接收方不安装 App 也能先完成关键动作时才可能裂变；若第一步就是下载、注册和填写长表单，实体卡会成为获客漏斗的阻塞点。

### 11.4 需要埋点的北极星与漏斗

- **候选北极星：** 每位激活用户每场活动产生的“有效协作连接数”。
- 有效协作连接不等于触碰次数，应至少满足：双方确认建立 Connection，并在 72 小时内由一方接受团队邀请，或双方进入同一项目并接受至少一个共同任务（口径与 [01-产品设计PRD.md](./01-产品设计PRD.md) §11.1 一致）。
- 核心漏斗：状态授权 → 资料完成 → 获得推荐 → 查看理由 → 发起请求 → 双方确认 → 组队／任务 → 7 日仍有协作行为。
- NFC 增量漏斗：读取成功率 → 页面打开率 → 请求发起率 → 确认率；必须与 QR／直接加微信做对照。

## 12. 关键风险与验证计划

| 优先级 | 风险 | 为什么致命 | 最小验证 | 通过信号 |
|---|---|---|---|---|
| P0 | 活动内网络密度不足 | 再好的推荐也没有足够候选人 | 在一场真实黑客松招募种子用户 | 用户能在 5 分钟内看到至少 3 个相关候选人 |
| P0 | 公开状态与隐私阻力 | 没有资料就没有匹配 | 测试临时授权、可见范围和到期时间 | 大多数测试者愿意公开最小资料集 |
| P0 | 匹配没有优于人工 | AI 只成为装饰 | 与随机／标签筛选做盲测 | 相关性、回复率或组队率出现明确提升 |
| P0 | 赛后留存接近零 | 无法成为独立 To C 产品 | 跟踪 7／30 日项目行为 | 用户在无赛事提醒下仍更新或复用关系 |
| P1 | NFC 不优于二维码 | 硬件失去必要性 | 同场 A/B 测试三种建联方式 | NFC 在成功率、速度或传播上有显著增量 |
| P1 | 个人不付费 | 商业闭环断裂 | 卡片预售＋单场 Premium 假门 | 出现真实支付而非口头兴趣 |
| P1 | 能力信息失真 | 匹配质量与信任崩溃 | 接入作品链接＋队友事后互评 | 证据资料比纯自报获得更高响应率 |
| P2 | 骚扰与滥用 | 公开状态带来安全风险 | 双向确认、限频、拉黑、举报 | 无需公开手机号也能完成有效建联 |

### 12.1 96 小时项目的研究型成功标准

不要用注册数判断成功。建议把 Demo 目标定义为：

1. 至少覆盖“未组队者、Idea 发起人、缺人的团队”三类身份；
2. 展示一个有解释的双向匹配，而不只是 AI 生成标签；
3. 用真实 NFC 或 QR 完成跨手机入口；
4. 建联必须经过双方确认；
5. 确认后自动生成角色建议与首批任务；
6. 全链路事件可被记录，以便现场验证漏斗。

## 13. 产品壁垒判断

### 13.1 不是壁垒的部分

- 被动 NFC 卡及印刷；
- 个人资料页和二维码；
- 通用大模型生成能力标签；
- Tinder 式滑动交互；
- 单场活动的参与者名单。

### 13.2 可能形成壁垒的部分

1. **局部网络密度：** 在特定黑客松、开源社区或创客圈率先形成“来这里就能找到合适搭档”的心智。
2. **协作结果图谱：** 记录谁和谁在什么项目中以什么角色合作、交付了什么、是否愿意再次合作。
3. **证据化身份：** 将 GitHub、作品、比赛结果、队友反馈和重复合作转化为比自填标签更可信的能力模型。
4. **匹配反馈数据：** 学习“被浏览—发起—接受—组队—交付—再次合作”的完整结果，而不只学习点击。
5. **跨活动分发网络：** 让卡片和账户在不同活动中复用，使每次线下活动都为长期网络增加节点和边。

**Inference：** 壁垒形成顺序应是“密度 → 有效连接 → 项目结果 → 更好匹配 → 更多密度”，而不是“先做硬件 → 自然形成社交网络”。在拿到跨多场活动的结果数据前，本项目只有产品差异，没有可靠壁垒。

## 14. 最终结论

### 14.1 是否值得作为黑客松项目

**值得。** 理由不是它完全没有竞品，而是它具备评委容易理解的现场冲突、实体交互和完整 Demo 闭环：一个未组队的人授权展示能力，AI 找到互补对象，双方碰触／确认，并立即得到团队启动方案。相比只展示聊天机器人或 NFC 名片，它更容易呈现“AI、硬件入口与真实协作结果”的关系。

### 14.2 是否已经证明能成为独立 To C 产品

**尚未。** 当前只证明了相邻需求真实存在，没有证明：

- 用户愿意持续维护协作身份；
- 黑客松之后仍会回来；
- AI 匹配显著优于标签和现场交流；
- NFC 显著优于二维码与微信；
- 个人愿意付费。

### 14.3 建议的战略表述

> 我们不是在做一张 NFC 名片，也不是只做黑客松组队工具。我们从黑客松这个高密度场景切入，为个人建立可授权、可验证、可持续进化的 AI 协作身份；让一次线下碰触不只交换联系方式，而是开启一段双方确认、可以立即执行、并能沉淀为下一次匹配证据的协作关系。

### 14.4 Go / No-Go 条件

- **继续投入：** 真实活动中能够形成足够密度；匹配带来高于基线的有效连接；出现赛后复用；至少一种 To C 付费测试出现真实支付。
- **缩减为活动功能：** 现场组队有效，但赛后留存长期偏低。
- **砍掉 NFC：** QR／链接的完成率相当或更高，且用户不愿携带卡片。
- **停止独立产品方向：** 即使有足够候选人，用户仍更愿意直接加微信、看 GitHub，且 AI 推荐与协作启动没有可测增量。
