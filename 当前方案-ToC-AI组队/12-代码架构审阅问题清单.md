# RALLY｜代码架构审阅问题清单

> 审阅日期：2026-08-29
> 审阅范围：手机端交互 Demo、Node.js 后端、SQLite 数据模型、API、测试与部署脚本
> 当前判断：仓库已经具备可演示的手机端原型和经过契约测试的后端状态机，但前后端主流程尚未真正打通，暂不具备完整上线条件。

## 一、验收现状

- 手机端静态流程自动化测试通过；
- 后端 HTTP 契约测试 48/48 通过；
- Live 浏览器端到端测试通过，已覆盖定位、离页撤销定位、公开状态、平台链接和基础 XSS 防护；
- 当前主要风险不在已测试的后端状态机，而在前后端集成、真实数据一致性、身份认证、HTTPS 部署和长期架构可维护性。

## 二、P0：阻塞真实使用或部署的问题

### P0-01 前端核心业务流程尚未接入真实后端

**现状**

手机端只有公开状态、外部平台链接和附近定位接入了真实 API。以下流程仍由浏览器内存模拟：

- 表达“想认识”；
- 连接请求、接受、拒绝、撤回和拉黑；
- 双卡碰触建联；
- 意图澄清和双方确认；
- 创建项目、邀请和确认入队；
- RALLY Room、任务认领和全员确认；
- 项目 SOS；
- 飞书和 GitHub 同步。

**影响**

刷新页面后状态丢失，两台真实设备无法通过当前前端完成完整协作闭环。后端 API 虽已实现并通过测试，但用户无法从产品界面使用。

**建议验收标准**

- 两个真实账号可在两台设备完成“发现—请求—确认建联—邀请—确认入队—认领任务”；
- 所有关键状态来自后端，刷新后能够恢复；
- 网络失败不误报成功，重复操作保持幂等。

### P0-02 缺少正式登录和会话初始化流程

**现状**

后端支持 Bearer Session，但前端没有登录、会话刷新、过期处理和退出登录界面，只会读取预先写入 `localStorage` 的 Token。演示身份依赖 `x-demo-user-id`，而部署配置默认关闭该不安全模式。

**影响**

默认部署后，普通用户没有从页面获得合法会话的路径，Live 模式无法直接使用。

**建议验收标准**

- 用户可通过明确的登录入口获得会话；
- 会话过期后有可理解的重新登录提示；
- 支持退出并撤销服务端 Session；
- 正式环境不依赖 `x-demo-user-id`。

### P0-03 部署脚本只有 HTTP，没有 HTTPS

**现状**

当前 Nginx 仅监听 80 端口，没有 TLS 证书、443、HTTP 到 HTTPS 跳转或 HSTS，与技术方案中“一个公网 HTTPS 域名”的要求不一致。

**影响**

- 真机 Geolocation 可能不可用；
- Bearer Token 存在明文传输风险；
- NFC/QR 公网页面不满足生产安全要求；
- 当前工程不能按设计作为公网 Live H5 使用。

**建议验收标准**

- 公网域名启用有效 HTTPS；
- HTTP 自动跳转 HTTPS；
- 真机定位、API 和 NFC/QR 落地页全部通过 HTTPS 工作；
- 密钥与 Token 不通过 URL 或明文链路传输。

## 三、P1：高优先级功能与数据问题

### P1-01 Live 用户详情可能被同 ID 的静态资料覆盖

**现状**

选择人物时会先查询静态人物数据，再查询 Live 附近列表。真实用户 ID 与预置人物 ID 相同时，附近列表显示后端资料，进入详情后却可能显示静态简介、项目和身份信息。

**影响**

列表和详情不一致，可能把虚构信息展示为真实用户资料。

**建议验收标准**

- Live 模式始终以服务端授权资料为唯一数据源；
- 静态人物只在明确的 Demo 模式使用；
- 自动化测试覆盖“静态 ID 与 Live ID 相同”的情况。

### P1-02 Live 初始化失败后不会自动恢复

**现状**

`/api/me` 只在页面启动时请求一次。后端启动较慢、网络波动、接口返回错误或登录过期时，页面不会重试，也没有手动重试入口。

**影响**

一次短暂故障会让整个 Live 会话持续不可用，只能刷新页面。

**建议验收标准**

- 请求失败时显示明确错误状态；
- 提供手动重试；
- 对临时网络错误进行有限次数退避重试；
- 401 与普通网络错误分别处理。

### P1-03 Live 定位失败时会回退到预置人物

**现状**

Live 模式发生定位或 API 错误后，“附近”页面会重新显示静态雷达人物。

**影响**

真实现场数据和演示数据混用，用户可能误把预置人物当作真实附近成员。

**建议验收标准**

- Live 模式失败时显示错误空态，不展示静态人物；
- Demo 数据必须有明显且持续的演示标识；
- 真实模式和演示模式的数据源不能自动混用。

### P1-04 意图澄清和方向治理没有后端模型

**现状**

前端展示了方向草案和双方确认，但后端没有实现以下领域实体：

- Intent Alignment；
- Direction Version；
- Direction Origin；
- Pivot/Fork；
- Leadership Term；
- Leader 交接；
- Change Request；
- Contribution Evidence。

**影响**

PRD 中强调的方向版本、发起归属和协作治理无法持久化，也无法审计或恢复。

**建议验收标准**

- 方向草案和成员确认写入服务端；
- 新方向通过版本或分支产生，不覆盖历史；
- 项目发起归属与当前 Leader 权限分开保存；
- 关键变更具有确认记录和 Event Log。

### P1-05 Leader 角色无法产生或交接

**现状**

数据库允许 `LEADER` 成员角色，权限判断也接受 Leader，但仓库中没有授予、撤销或交接 Leader 的接口和业务流程。

**影响**

所有 Leader 权限分支实际上不可达，项目长期只能依赖 Originator 执行治理操作。

**建议验收标准**

- Leader 通过显式任期产生；
- 支持交接、结束和历史查询；
- Leader 变化不修改项目发起归属；
- 权限测试覆盖任期开始和结束。

### P1-06 缺少连接请求的轮询或实时同步

**现状**

后端已经提供连接请求箱，但前端没有轮询、SSE、WebSocket 或可靠的手动刷新流程。

**影响**

两台设备无法在前端实时看到请求到达、接受、拒绝和撤回状态。

**建议验收标准**

- 请求箱在合理时间内同步新状态；
- 页面恢复前台后立即刷新；
- 弱网重连后不会重复创建 Connection；
- 服务端仍作为最终状态来源。

### P1-07 推荐页和名册页仍使用静态人物数据

**现状**

Live 模式只有“附近”读取后端数据，“推荐”和“名册”仍使用 11 个预置人物。

**影响**

公开授权、退出活动、拉黑、资料修改和真实项目缺口不会反映到推荐与名册中。

**建议验收标准**

- 三种发现方式统一读取真实活动成员；
- 推荐调用服务端 Discover/Matching 数据；
- 暂停公开、拉黑和退出活动后，各发现入口同步移除该成员。

### P1-08 Agent 推荐和计划仍是固定输出

**现状**

推荐理由、风险、人物项目资料和前端任务主要来自静态文案。后端启动包也是固定模板降级，没有真实模型调用链。

**影响**

当前 Agent 只能证明交互形式，不能证明真实资料输入、结构化生成、失败降级和结果追溯能力。

**建议验收标准**

- 明确区分规则匹配、模板降级和模型生成；
- 模型输出通过结构校验；
- 模型超时或失败时主链继续运行；
- 保存生成来源、版本和用户确认记录。

### P1-09 公开字段编辑和设置页尚未完成

**现状**

能力与项目证据、隐私与授权、通知、设备与数据、卡片公开内容等入口仍显示“下一轮接入”。

**影响**

后端虽然支持资料与逐字段公开，用户仍无法从前端控制自己的真实公开范围。

**建议验收标准**

- 用户可编辑资料和逐字段授权；
- 保存前展示实际公开预览；
- 暂停、恢复和过期规则保持一致；
- NFC、名册、推荐和附近只返回已授权字段。

### P1-10 当前工程不是真正的 PWA

**现状**

项目没有 Web App Manifest、Service Worker、离线缓存、安装入口、应用图标或离线失败页。

**影响**

目前是响应式静态网页，不能满足文档中“Web/PWA”及现场弱网兜底的完整要求。

**建议验收标准**

- 提供 Manifest 和应用图标；
- 支持安装到桌面；
- 静态壳和必要演示资源可离线打开；
- 离线状态不会误报业务请求成功。

## 四、P2：交互、稳定性与完整性问题

### P2-01 简介页向下退出时可能触发完整资料重排

**现状**

简介页识别到纵向手势后，不区分上拉或下拉就解除完整资料遮挡。下拉退出时，隐藏内容也可能短暂参与布局。

**影响**

慢速设备上可能出现闪动、跳动或短暂露出后续资料。

**建议验收标准**

- 只有向上展开时解除完整资料遮挡；
- 向下退出不触发内容重排；
- 在低性能移动设备上验证连续拖动。

### P2-02 浏览器返回键没有对应产品导航

**现状**

详情、筛选、设置和业务弹层没有写入浏览器历史；`popstate` 只处理发现页 Variant。

**影响**

Android 返回键或浏览器返回手势可能直接离开产品，而不是关闭当前界面或返回发现。

**建议验收标准**

- 浏览器返回优先关闭弹层或详情；
- 再次返回才离开当前产品页；
- URL 与当前主要界面状态保持一致。

### P2-03 异步操作缺少防重复和竞态控制

**现状**

可见状态、平台链接保存和删除没有统一的请求中状态、按钮禁用或请求版本控制。

**影响**

用户快速重复点击可能发送并发请求，旧请求晚返回后可能覆盖新状态。

**建议验收标准**

- 请求期间按钮进入明确 loading 状态；
- 同一资源只允许一个在途修改；
- 过期响应不能覆盖较新的用户操作。

### P2-04 飞书和 GitHub 同步未实现

**现状**

同步按钮只显示“已生成同步包（Demo）”，没有 OAuth、目标选择、字段映射或真实写入。

**建议验收标准**

- 用户明确授权第三方平台；
- 写入前展示目标与内容；
- 保存外部对象 ID 和同步结果；
- 支持失败重试与撤销说明。

### P2-05 NFC/QR 客户端流程不完整

**现状**

后端已有卡片 Token 和物理双卡握手接口，但手机端仍使用“模拟碰卡”按钮。

**缺失内容**

- QR 展示与扫描；
- NFC 落地页完整交互；
- 双卡设备挑战与设备绑定；
- 换卡、失效和撤销；
- 离线待同步状态；
- iPhone/Android 兼容提示。

## 五、架构技术债

### A-01 前端单文件体积过大

`prototype/mobile-demo/app.js` 已超过 2300 行，同时承担数据、状态、模板、API、手势、导航和事件绑定。

建议至少拆分为：

- domain/state；
- API client；
- discovery；
- person profile；
- connections；
- projects/room；
- profile/settings；
- gestures；
- shared rendering/components。

### A-02 全量 `innerHTML` 重渲染带来性能风险

每次状态变化都会重建整个应用 DOM，并重新绑定事件。该方式容易造成滚动位置、焦点、输入状态和动画中断，也是卡片交互卡顿的结构性风险。

建议将拖动动画与业务状态更新分离，只更新发生变化的区域，或迁移到具有稳定组件生命周期的前端框架。

### A-03 后端产品模块职责过重

`backend/src/product-module.js` 接近 3000 行，混合了建表、SQL、业务规则、路由、校验和序列化。

建议按活动资料、发现、项目、Room、SOS 和平台链接拆分服务，并将数据库访问和 HTTP 适配层分离。

### A-04 数据库迁移缺少版本管理

当前迁移依赖运行时检查和零散 `ALTER TABLE`，没有明确 Schema Version、迁移顺序或回滚机制。

建议引入只增不改的迁移文件、迁移记录表、备份检查和升级回归测试。

### A-05 工程质量门禁不足

当前没有发现完整的 CI、Lint、格式检查、类型检查和覆盖率门槛。

建议在 Pull Request 上至少执行：

- JavaScript 静态检查；
- 后端 48 项契约测试；
- 手机 Smoke Test；
- Live E2E；
- OpenAPI 与实现一致性检查；
- Git 工作区和生成物污染检查。

### A-06 生产安全与运维能力未完成

当前 API 使用全局 `Access-Control-Allow-Origin: *`，部署也缺少数据库备份、恢复、监控、告警、日志轮转和零停机升级。

建议生产化前完成：

- CORS 域名白名单；
- HTTPS 与安全响应头；
- PostgreSQL 或明确的 SQLite 单机边界；
- 自动备份与恢复演练；
- 服务健康、错误率和磁盘告警；
- 密钥轮换与最小权限管理。

## 六、建议实施顺序

1. 完成 HTTPS、正式登录和会话管理；
2. 修复 Live 详情数据覆盖、失败重试和真假数据混用；
3. 将连接请求、建联、邀请、入队和 Room 主链接入真实后端；
4. 增加连接请求轮询或实时同步；
5. 实现资料编辑与逐字段公开；
6. 建立方向版本、发起归属和 Leader 任期模型；
7. 接入真实推荐/Agent，并保留确定性降级；
8. 补齐 PWA、NFC/QR、跨工具同步和生产运维；
9. 拆分前后端大文件，建立 CI 和工程质量门禁。

## 七、发布判断

当前版本可以用于产品流程评审、视觉验证和受控现场演示，不建议直接作为公开生产产品发布。达到可公开试用状态前，至少应关闭全部 P0，并完成前后端真实建联与入队主链、Live 数据真实性修复和 HTTPS 部署。
