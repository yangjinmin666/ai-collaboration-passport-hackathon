# COSPAN｜共域：手机端可交互 Demo

## 1. Demo 目的

这份 Demo 用来验证手机端能否承接 AI Passport 的完整价值链：

> 发现附近的人 → 理解 AI 匹配理由 → 当面碰卡建联 → 人类意图澄清 → 双方确认方向 → 创建项目并邀请入队 → AI 生成启动任务 → 开始协作。

它仍是用于产品判断和黑客松展示的原型，不是生产 App，但已经提供两种运行模式：默认模式使用预置角色和页面内存状态；`live=1` 模式会连接真实 Node 后端，使用浏览器 Geolocation 发布短时位置，并真实保存／删除外部平台链接。碰卡动画、意图澄清、推荐顺序和部分协作空间 UI 仍是演示态；NFC／QR 建联、团队、任务与 SOS 的后端状态链已由独立 HTTP 测试跑通，方向草案的服务端状态门禁仍待接入。

手机端字号、颜色、间距、触控和跨终端规则见 [10-移动端视觉与字体规范](./10-移动端视觉与字体规范.md)。

## 2. 产品分工

| 终端 | Demo 中的职责 |
|---|---|
| 手机端 | **现场主入口与伴随端**：编辑协作身份，在“发现”中切换推荐／附近／名册，管理连接、邀请入队、认领／确认首次分工，并处理关键动态与 SOS |
| 宽屏端 | **COSPAN Space 主工作台**：查看成员权限、Agent 分工提案、启动任务和受保护记录；不承接聊天、在线文档或长期项目管理 |
| AI Passport | 碰前公开身份与组队状态、卡对卡握手、最小成功／失败反馈；不承担附近人员扫描、名册或完整交互 |
| NFC／QR 兼容入口 | 没有 AI Passport 时，用普通手机打开有限公开页并发起连接请求 |

Demo 中的“模拟碰卡”代表未来两张有源 AI Passport 完成近距离检测和双方握手；它不限定量产版本必须依靠 NFC P2P。

## 3. 运行方式

原型目录：[prototype/mobile-demo](./prototype/mobile-demo/README.md)

```bash
cd prototype/mobile-demo
./run.sh
```

打开：

- [发现 · 推荐](http://localhost:4173/?variant=A)
- [发现 · 附近](http://localhost:4173/?variant=B)
- [发现 · 名册](http://localhost:4173/?variant=C)

连接真实后端的附近页：

```text
http://localhost:4173/?variant=B&live=1&apiBase=http://127.0.0.1:8787&demoUser=user-zhou
```

其中 `demoUser` 仅用于本地可信环境；需要后端开启 `ALLOW_INSECURE_DEMO_AUTH=1`。生产接入应由 `localStorage.rally_access_token` 提供 Bearer Token；此时 URL 中的 `apiBase` 会被忽略并默认只访问同源 API。可信应用若采用独立 API 域名，应在登录初始化阶段写入 `localStorage.rally_api_base`。浏览器真实定位要求 `localhost` 或 HTTPS。

## 4. 同一发现页的三种浏览方式

| 浏览方式 | 核心表达 | 更适合验证什么 |
|---|---|---|
| 推荐 | 项目缺口和可解释优先顺序 | AI 是否能让用户更快找到值得聊的人 |
| 附近 | 空间关系和“人就在附近”优先 | 手机前台发现是否能降低线下搭话成本 |
| 名册 | 在自己的手机上浏览本场已授权成员 | 完整查找、筛选和回看是否有价值 |

默认使用“推荐”作为主演示入口。三种方式通过手机端“发现”页内的分段控件切换，共用同一批人物、详情、授权和关系数据。协作护照完整编辑放在“我的”。

### 4.1 用户控制的发现筛选

发现页左上角提供统一的“筛选偏好”入口，已启用条件数量通过小型蓝色徽标反馈。设置层实时显示“本场公开成员数 → 符合人数”，并支持：

- 协作状态：正在找队伍、团队正在招人、可交流／可支援；
- 需要的职能：硬件／结构、设计／路演、AI／算法、产品／研究、增长／运营、安全／隐私；
- 最低可投入时间：不限、至少 2／4／8 小时；
- 现场范围：整个会场、附近、很近；
- 是否必须存在公开项目证据。

同类选项内部为“满足任一”，不同筛选条件之间为“同时满足”。这些条件决定候选是否出现；AI 只解释和排序，不修改用户条件，也不生成对人的匹配百分比。0 人符合时展示明确空状态，不静默放宽范围。当前 Demo 已完整可点击并同步作用于推荐、附近和名册；Live 后端仍需把投入时间、职能类别和证据状态升级为结构化字段后再接入生产筛选。

## 6. 90 秒演示脚本

1. **问题（8 秒）：** 黑客松现场真正困难的不是加微信，而是不知道谁还没组队、谁能补齐项目缺口、为什么值得聊。
2. **发现（12 秒）：** 在推荐页一屏浏览一位互补搭档，左滑暂不看、右滑表达“想认识”。
3. **解释（12 秒）：** 点击林澈的单人卡片，查看能力证据、AI 推荐理由和一项需要先确认的风险；不展示标准化匹配分。
4. **碰卡（12 秒）：** 两人在现实中交流后直接“模拟碰卡”，形成带真实相遇来源的协作关系；线上“想认识”可另行演示，不是碰卡前置步骤。
5. **意图澄清（14 秒）：** 双方表达各自意图，共同填写“服务谁／解决什么／验证什么”；AI 只整理，不替人决定。
6. **确认并入队（10 秒）：** 两人分别确认方向后，创建“离线会议洞察终端”并邀请林澈入队。
7. **启动协作（17 秒）：** COSPAN Space 根据成员能力生成角色覆盖、风险与三个启动任务；成员主动认领并由人确认方案。
8. **硬件联动（5 秒）：** 在“我的”里展示未来墨水屏公开面，并暂停／恢复现场可见状态。

补充展示可进入“我的 → 外部平台与作品”：GitHub 可显示公开资料摘要；作品站、即刻、小红书和抖音只显示用户主动提交的链接与“用户提交”标识。

## 7. 当前验收结果

- 推荐／附近／名册在同一手机端发现页内切换，无额外原型切换器；
- 推荐模式一次展示 1 张主卡并可连续刷完 11 人，附近模式动态排布 11 人，名册模式展示 11 人；
- 推荐卡支持左右拖动和按钮操作：左滑暂不看、右滑想认识、点卡查看完整信息；
- 左上角可设置筛选偏好，实时预览人数并同时过滤推荐、附近和名册；0 人时不自动放宽；
- 发现、匹配解释、打招呼、碰卡、确认建联、意图澄清、双方方向确认、入队与任务接受完整可点击；
- “连接”“协作”“我的”会反映前序操作形成的状态；连接保存关系，协作承载具体项目启动舱；
- 手机启动舱显示项目进度、Agent 分工确认、最近动态与 SOS；宽屏工作台显示三栏治理视图；
- 公开状态开关会同步改变手机发现页和墨水屏预览；
- Live 模式下，进入附近页才调用真实手机定位；离开该页、暂停公开或关闭页面会删除服务端位置心跳；其他用户只能得到距离分桶，看不到经纬度；
- Live 模式下，“我的”可以读取、保存和移除外部平台链接；GitHub 公开摘要与用户提交链接在视觉上明确区分；
- 已在 390×844 手机视口运行自动化验收，无 JavaScript 控制台错误和横向溢出；普通手机 UI 最小字号为 10px，主要触控目标不小于 44px（墨水屏缩略预览与雷达空间头像为明确例外）。
- `python3 live_e2e_test.py` 已用真实 Node 进程和浏览器权限验证：位置发布成功、附近返回 1 人、离页删除位置、平台链接保存／展示／删除，浏览器错误为 0。

## 8. 评审后要冻结的决策

1. 推荐、附近和名册的默认顺序与入口展示强度；
2. “打招呼”和“碰卡确认”是否保留为两个步骤；
3. 附近首页优先展示人、项目，还是当前团队缺口；
4. 工牌最小公开面与手机协作护照需要共享哪些最小识别元素；
5. 进入工程版本前，是吸收已验证流程还是删除本原型重建。
