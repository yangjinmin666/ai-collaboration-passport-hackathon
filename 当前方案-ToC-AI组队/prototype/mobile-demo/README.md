# RALLY｜集结 手机端交互 Demo（Prototype）

> PROTOTYPE — 这是用于确认产品流程和视觉方向的抛弃式原型，不是生产代码。

视觉实现遵循 [10-移动端视觉与字体规范](../../10-移动端视觉与字体规范.md)。

## 需要回答的问题

手机端如何作为现场主入口与伴随端，承接“组装协作护照 → 发现 → 表达想认识／线下碰卡 → 连接 → 入队 → RALLY Room 分工确认”，并在宽屏呈现项目启动舱主工作台？

## 运行

```bash
./run.sh
```

静态原型只依赖本机 Python 3，不需要安装前端依赖。建议使用 Chrome、Safari 或手机浏览器打开。

浏览器打开：

- [发现 · 推荐](http://localhost:4173/?variant=A)
- [发现 · 附近](http://localhost:4173/?variant=B)
- [发现 · 名册](http://localhost:4173/?variant=C)
- [新用户引导 — 协作护照组装](http://localhost:4173/?variant=C&onboarding=1)
- [预置 RALLY Room](http://localhost:4173/?variant=A&workspace=1)

三种浏览方式通过手机“发现”页内的分段控件切换；协作护照完整编辑统一放在“我的”。

## 演示路径

1. 从协作状态与已有项目证据组装协作护照；
2. 在“发现 · 推荐”中一屏浏览一位候选人，左滑暂不看、右滑想认识、点卡查看完整理由；
3. 表达“想认识”，或独立点击“模拟碰卡直连”；两条路径不互为前置；
4. 邀请对方加入项目；
5. 在 RALLY Room 中查看 Agent 建议，主动认领并由人确认首次分工；
6. 在“连接”和“协作”中分别查看长期关系与具体项目；
7. 确认后查看轻量伴随状态、我的启动任务和项目 SOS；
8. 在“我的”中切换活动内可见状态，预览未来墨水屏内容。

默认静态模式的交互状态只保存在内存中，刷新页面后重置。开启 Live 模式后，活动公开状态、平台链接和临时位置会写入真实后端；连接、入队、Room 与 SOS 的手机界面仍是流程原型，真实状态机通过后端 API 与测试验证。

## Live 模式

先启动 `../../backend`，再打开：

```text
http://localhost:4173/?variant=B&live=1&apiBase=http://127.0.0.1:8787&demoUser=user-zhou
```

Live 模式会读取后端 `/api/me` 的授权状态；手机“我的”中的暂停／恢复会同步到活动可见性接口。只有打开“发现 · 附近”且状态可见时才启用浏览器 Geolocation，离开页面或暂停公开会撤销位置。平台资料只保存用户主动提交的 HTTPS 链接；GitHub 可同步公开摘要，其他平台不爬取内容。

## Demo 边界

- 静态模式的附近人员和信号强度为预置数据；Live 模式使用手机 Geolocation 与后端距离分桶，不向他人返回经纬度；
- 推荐页一次聚焦一人并可连续刷完 11 个预置角色，附近和名册也使用完整候选集；
- 卡对卡碰触由按钮模拟；
- AI 推荐理由、风险和任务为预置输出，不向用户显示综合匹配分数；
- 手机端只展示启动进度、分工确认、关键动态和 SOS；宽屏三栏工作台不包含聊天、在线文档或长期项目管理；
- 尚未接入正式账户登录、BLE、NFC P2P、生产短信与服务器部署；Live 模式使用演示身份或 Bearer Token 接入当前后端。

## 验收

```bash
python3 smoke_test.py
```

验收截图输出到 `artifacts/`。脚本会检查三种发现浏览方式、完整协作闭环、公开状态同步、横向溢出、浏览器错误，以及手机普通 UI 的最小字号与触控目标。
