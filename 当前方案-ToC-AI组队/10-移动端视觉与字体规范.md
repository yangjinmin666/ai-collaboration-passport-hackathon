## 1. 产品定义与原则

### 1.1 一句话定义

产品名称：**COSPAN｜合拍**；英文读法：**Co-Span**。

COSPAN 是服务于黑客松、展会和线下协作现场的 AI 组队与启动产品：帮助用户发现值得认识的人，在真实建联后澄清共同意图，并把新关系推进到可确认的项目方向与首次分工。

主 Slogan：

> 人与人先相遇，人与 Agent 再共创。
> Meet as people. Build with agents.

品牌标志采用“**双手击掌**”图形：两只白色深墨线稿手从左右拍合，中央冲击星表示发生连接，主蓝与深蓝爆发形表达相遇后立即启动协作。图形使用浅色圆角底以保留线稿呼吸感，并将手形控制在移动端安全区内；小尺寸场景只使用图形标，完整品牌锁定为“图形标＋COSPAN＋合拍”。

### 1.2 核心价值链

```text
组装并授权协作护照
→ 发现人／团队缺口／项目 SOS
→ 线上表达意愿或线下碰卡
→ 建立连接
→ 意图澄清
→ 双方确认方向
→ 创建项目或接受项目邀请
→ 进入 COSPAN Space
→ Agent 提出分工建议
→ 人认领、调整并确认
→ 转入飞书、GitHub 等工具执行
```

### 1.3 产品原则

1. **先建立信任，再进入协作。** “想认识”、正式建联、加入项目是三次不同决定。
2. **AI 解释和建议，人做选择。** 不展示综合匹配百分比，不让 Agent 自动定方向或静默派活。
3. **先澄清方向，再创建项目。** 方向未确定时不生成任务、不分配负责人。
4. **手机是现场主端。** 手机负责发现、建联、确认和伴随；复杂治理在宽屏展开。
5. **COSPAN Space 是启动舱。** 不复制聊天、在线文档、网盘、代码托管和通用项目管理。
6. **硬件是增强项。** NFC、二维码和墨水屏可以增强现场感，但移除硬件后软件闭环仍必须成立。
7. **默认最小公开。** 用户只公开自己明确授权的字段，并能暂停、撤回和删除。
8. **简约优先。** 一屏聚焦一个主要判断或行动，减少边框、套卡、阴影和重复标题。

## 2. 场景与功能层级

### 2.1 四层产品结构

| 层级 | 内容 | 生命周期 |
|---|---|---|
| COSPAN 常驻层 | 协作护照、推荐／附近发现、连接、协作、个人设置 | 跨活动长期存在 |
| 展会空间层 | 当前命名展会、展会内可见性、现场发现、急聘与 SOS | 受具体活动时间约束 |
| 展会限定层 | 展会名册及主办方配置能力 | 只在特殊展会显式开启 |
| 长期留存层 | 已确认连接、项目、分工基线与贡献记录 | 展会结束后继续保留 |

### 2.2 展会名册规则

“名册”不是常驻功能，也不是附近的人列表。

- 只有主办方为某个特殊展会开启 `directoryEnabled` 时，发现页才显示“名册”；
- 名册只收录明确授权参加该场展会的成员；
- 展会结束、授权到期或主办方关闭后，名册入口和临时公开内容消失；
- 普通场景的发现页只保留“推荐／附近”；
- 已确认的连接、项目与协作记录不随名册关闭而删除。

## 3. 手机端信息架构

底部一级导航固定为四项：

| Tab | 核心任务 | 主要内容 |
|---|---|---|
| 发现 | 找到值得认识或支援的人 | 推荐、附近、特殊展会名册、团队急聘、项目 SOS |
| 连接 | 管理跨活动的人际关系 | 想认识、待回应、已建联、相遇来源、共同项目 |
| 协作 | 把关系推进为明确行动 | 组队邀请、意图澄清、项目、COSPAN Space、分工确认、动态与 SOS |
| 我的 | 管理对外身份与本人控制 | 协作护照、公开状态、能力证据、外部平台、工牌预览、设置 |

结构规则：

- “碰卡”是现实中的跨页面事件，不是第五个 Tab；
- “协作护照”是身份底层，不是发现页的独立方向；
- “项目”归入协作，不单独占用一级导航；
- “设备与隐私”“数据与授权”“展会与账号管理”和动效／声效偏好放入“我的 → 设置”；“退出当前账号”可作为“我的”页末唯一的低频会话操作保留；
- “我的”左上角显示 44×44px 圆形设置图标，但整个顶部随页面正常滚动，不做 `sticky` 或 `fixed`；
- 当前展会用轻量活动胶囊表达，不把活动信息做成第二条固定导航。

## 4. 核心用户流程

### 4.1 新用户进入

```text
开屏 → 选择微信／Google／手机号登录 → 最小身份 → 协作状态与需求 → 能力和证据 → 预览 → 明确授权 → 发现
```

登录只完成身份验证，不强制填写昵称。新用户登录成功后进入最小身份编辑，再补充姓名／昵称、头像、当前角色、协作状态和当前需求；外部平台资料不是注册阻断项，可稍后补充。手机号、微信与 Google 都不得自动公开手机号或邮箱。Android 的 Google 授权使用系统浏览器、客户端 verifier 和经过域名关联验证的 HTTPS App Link 返回；微信当前为微信内网页授权，原生入口在 OpenSDK 接入前必须明确标记不可用。

### 4.2 线上与线下建联

| 用户动作 | 产品语义 | 是否建立正式连接 |
|---|---|---|
| 左滑／暂时略过 | 当前不优先看，不是负面评分 | 否 |
| 右滑／想认识 | 可撤回的单方交流意愿 | 否 |
| 被动 NFC／二维码 | 打开有限公开页并发起请求 | 需对方确认 |
| 双方主动碰卡 | 双方在场并共同表达建联授权 | 是 |
| 邀请入队 | 将关系带入明确项目 | 需单独确认 |
| 接受 SOS | 进入短时援助会话 | 不默认入队 |

### 4.3 建联后的意图澄清

当项目方向尚未确定：

1. 双方分别表达问题兴趣、投入边界和期望结果；
2. Agent 只整理重合点、分歧和待确认问题；
3. 由人共同确认“服务谁／解决什么／验证什么”；
4. 未确认前只保存方向草案，不创建项目、Leader、成员或任务；
5. 双方确认后，才创建项目或接受已有项目邀请。

### 4.4 入队与 COSPAN Space

- 已有项目发送明确项目邀请；尚无项目则在方向确认后创建；
- 受邀者单独确认后才生成 Membership，拒绝或超时必须有明确状态；
- 成员到齐后，Agent 生成可修改的角色覆盖、风险、任务和完成标准；
- 成员主动认领或调整，被指派者明确接受，团队再确认计划基线；
- `Assignment Proposal` 不能直接写入正式负责人；只有人确认后才能产生 `confirmed_owner`；
- 启动完成后将日常执行移交飞书、GitHub 等已有工具。

## 5. 多终端职责

| 终端 | 主要任务 | 信息密度与交互 |
|---|---|---|
| 手机／PWA／Android | 发现、建联、现场确认、协作伴随 | 单列、14px 正文、44px 触控、一个主行动 |
| 宽屏 COSPAN Space | 项目启动与治理 | 多栏、完整建议理由、计划基线、变更与贡献记录 |
| ESP32-8048S043 竖向工牌 | 展示本人最小公开状态并触发碰卡 | 旋转后 480×800 竖屏、高对比、无复杂浏览与编辑 |
| 飞书／GitHub 等外部工具 | 日常沟通、文档、代码和长期执行 | COSPAN 只做确认后的移交，不复制其能力 |

手机端 COSPAN Space 首屏只展示项目状态、启动进度、当前需要我确认的事项、我的任务、关键动态和 SOS；复杂权限、完整编排和长期记录在宽屏展开。

## 6. 视觉目标

COSPAN 的手机端服务于黑客松、展会和线下协作现场。用户需要在移动、交谈和时间压力下快速完成浏览、建联与确认，因此视觉系统优先保证：

1. 一屏只突出一个主要判断或行动；
2. 正文在真机上可直接阅读，不使用被缩小的设计稿字号；
3. 黑白灰承担信息层级，蓝色只表示行动、选择和实时信号；
4. 人物、能力证据和项目状态比装饰更醒目；
5. 手机、电脑 COSPAN Space 与 4.3 英寸硬件展示屏属于同一产品，但不复制彼此的信息密度。

## 7. 品牌颜色

### 7.1 基础 Token

| Token | 色值 | 用途 |
|---|---:|---|
| `--paper` | `#F7F8FA` | 页面浅灰白底色 |
| `--white` | `#FFFFFF` | 卡片、浮层和选中 Tab |
| `--ink` | `#17212D` | 标题、正文和主要图标 |
| `--muted` | `#6F7B89` | 次要说明、时间和元信息 |
| `--line` | `#D6DDE7` | 边框、分割线和未激活轮廓 |
| `--profile-detail-surface` | `#F5F6F2` | 人物详情中同层级信息模块的统一浅灰白底 |
| `--cobalt` / `--guide-blue` | `#347CF8` | 主要按钮、选中状态、Logo 外层和关键实时信号 |
| `--cobalt-deep` / `--guide-blue-deep` | `#245FC8` | Logo 中层、蓝色文字与高对比交互态 |
| `--signal` | `#EAF2FF` | 蓝色状态的浅色背景 |
| `--guide-blue-soft` | `#F0F5FF` | 引导说明和轻量提示背景 |

### 7.2 使用规则

- 页面不使用大面积蓝色底或装饰性渐变；
- 一个视区原则上只保留一个实心蓝色主行动；
- 蓝色不代表“匹配分高”，只代表可行动、已选择、进行中或需要关注；
- 危险色（Danger / Destructive）为红色，只用于删除账号、永久清除数据、不可恢复撤销等高风险或不可逆操作；
- 退出当前账号只是可恢复的会话操作，使用白底、`--line` 描边和 `--ink` 文字，不得使用红色危险态；
- 提醒／警告色（Warning）使用黄橙语义，不与红色危险态混用；错误状态可以使用红色，但必须同时提供明确错误文案；
- 成功、警告、错误和危险操作使用各自独立语义，不能长期都借用品牌蓝；
- 普通正文优先使用 `--ink`，辅助文字使用 `--muted`，不要用低透明度文字代替明确色值。

## 8. 字体系统

### 8.1 字体栈

```css
font-family: "SF Pro Display", "PingFang SC", "Helvetica Neue", Arial, sans-serif;
```

中文以苹方为真机基准，数字和英文沿用系统无衬线字体。编号、时间戳、微标签和硬件屏状态可使用等宽字体，但不用于长段正文。

### 8.2 字号与行高

| 层级 | Token | 字号 | 建议行高 | 典型用途 |
|---|---|---:|---:|---|
| 展示标题 | `--type-display` | 28px | 1.15 | 人名、核心结果 |
| 页面标题 | `--type-page-title` | 24px | 1.3 | 名册、COSPAN Space 项目名 |
| 分区标题 | `--type-section-title` | 18px | 1.3 | 模块标题、人物详情标题 |
| 卡片标题 | `--type-card-title` | 16px | 1.3–1.4 | 状态、任务和证据标题 |
| 正文 | `--type-body` | 14px | 1.5 | 推荐理由、说明和关键内容 |
| 标签／辅助 | `--type-label` | 12px | 1.4–1.5 | 标签、时间、按钮辅助信息 |
| 英文微标签 | `--type-micro` | 10px | 1.4 | Eyebrow、编号和少量元数据 |

### 8.3 强制规则

- 手机端普通可见文字不得小于 10px；
- 连续阅读正文从 14px 起，不用 10–12px 承载完整句子；
- 12px 只用于标签、时间和单行辅助信息；
- 10px 只用于短英文微标签、编号和低权重元数据；
- 标题最多两级同时出现，避免同屏出现过多粗体；
- 中文正文默认行高 1.5，长句不得使用紧行高；
- 省略号只用于可以点开查看完整内容的区域。

## 9. 间距与布局

COSPAN 使用 8px 基础节奏，并保留 4px 处理图标、标签和紧密元素之间的微间距。

| Token | 数值 | 用途 |
|---|---:|---|
| `--space-1` | 4px | 图标与文字、标签内部微间距 |
| `--space-2` | 8px | 同组元素间距 |
| `--space-3` | 12px | 卡片内部紧凑间距 |
| `--space-4` | 16px | 页面左右边距、标准卡片内边距 |
| `--space-5` | 24px | 分区间距 |
| `--space-6` | 32px | 大模块或流程阶段间距 |

布局规则：

- 390px 基准视口使用 18px 左右页面边距，生产版可收敛为 16px Token；
- 主要卡片内容距边缘不少于 16px；
- 顶部、底部和横屏边缘使用 `safe-area-inset-top/right/bottom/left` 适配状态栏、圆角和手势区；
- 手机页面使用 `100dvh` 处理动态浏览器高度，不能只依赖固定 `100vh`；
- 底部导航为悬浮层时，页面必须预留至少 96px 的底部滚动空间，并叠加真实底部安全区；
- 页面最后一个内容块必须可以完整滚入导航上方，不能出现底部卡片被裁切；
- 推荐页一次聚焦一位候选人；附近与名册承担全局浏览，不把推荐页压成表格；
- 推荐主卡大小以信息完整、按钮可触达和底部不裁切为准，不通过缩小字号硬塞内容；
- 能用分区标题、留白和分割线表达层级时，不再额外套一层卡片；
- 同一详情页内处于同层级的内容模块统一使用浅灰白表面；不得用蓝、紫等不同彩色背景强行区分“协作方式”“能力证据”“系统推荐参考”，差异通过标题、标签、留白和细分割线表达；
- “我的”页面顶部随内容正常滚动，禁止增加 `sticky` 或 `fixed` 顶栏；
- 不允许页面产生横向滚动。

## 10. 圆角、边框与阴影

| 层级 | 圆角 | 使用范围 |
|---|---:|---|
| 大容器 | 30px | 推荐主卡、核心结果卡 |
| 标准卡片 | 22px | 模块卡、浮层、COSPAN Space 卡片 |
| 控件 | 16px | 按钮、输入区、分段控件 |
| 胶囊 | 999px | 状态、标签、头像 |

- 默认边框为 1px `--line`；
- 普通列表优先使用留白和分割线，不给每一行增加完整外框；
- 阴影只用于悬浮导航、主推荐卡、设置圆形按钮和浮层，普通列表不用阴影堆层级；
- 阴影不能替代边框，浅灰白页面上仍需保持卡片轮廓；
- 相邻容器不同时使用边框、阴影、色块和大圆角表达同一层级；
- 人物头像一律为正圆，素材使用居中裁切，不露出灰色底边。

## 11. 触控与反馈

- 主要交互目标的包围盒不得小于 44×44px；横向按钮可以更宽，但高度仍不得小于 44px；
- Switch 的可点击包围盒不得小于 44×44px，但可见轨道统一为约 46×28px；不得为了满足触控面积而把整块 44px 高的按钮都涂成开关色；
- 底部导航单项高度不低于 56px；
- 推荐卡的“暂不看／看详情／想认识”需要同时提供图形和文字，不能只靠颜色区分；
- 点击、选中、等待和完成必须有可见反馈；
- 焦点态使用 3px 蓝色轮廓，并与控件保持 3px 间距；
- 附近雷达中的头像是空间可视化例外，可低于 44px，但选中后应在下方生成标准尺寸的操作卡，不能要求用户只点极小头像完成关键操作；
- 尊重系统的减少动态效果设置，核心流程不能依赖动画才能理解。

## 12. 核心组件规范

### 12.1 顶部品牌区

- 发现页展示 `COSPAN`、中文品牌名与当前一级模块；连接、协作等任务页只显示当前模块标题，避免品牌、范围和任务标题形成三个竞争层级；
- 右侧范围入口必须同时显示“当前范围”和具体活动／日常附近，不能只靠图标表达；
- 发现页左上角可以使用筛选入口；“我的”左上角使用圆形设置入口；
- 活动胶囊不承担附近雷达开关，品牌区不使用大面积品牌色；
- 普通业务页面的顶部随内容滚动，只有独立多步编辑器或全屏浮层内部导航可按需吸顶。

### 12.2 分段控件

- 用于同一模块内的并列视图，如“推荐／附近／名册”和“概览／任务／记录”；
- “名册”按活动配置条件化出现，普通场景不占空位；
- 高度至少 44px；
- 未选中项使用灰字，选中项使用白底或蓝色底线中的一种；
- 不同时使用底线、实心背景和投影表达同一选中状态。

### 12.3 人物推荐卡

- 首屏依次回答：对方状态、身份、能力标签、证据、推荐理由和待确认项；
- 不显示标准化匹配百分比；
- AI 输出用“为什么建议认识”解释，不伪装为客观评分；
- 卡片正面只放快速决策信息，完整经历进入详情浮层；
- 左滑表示“暂时略过”，右滑表示“想认识”，都不等于正式建联；
- 点击卡片先打开预览面板，上滑展开完整资料，下滑收起。

### 12.4 状态标签

- 文案必须能独立表达含义，颜色只作为强化；
- 主状态与实时信号分开：如“团队补位中”是主状态，“项目 SOS”是实时信号；
- 标签默认 12px；空间极紧时可使用 10px，但不得承载长句。

### 12.5 按钮

- 实心蓝色：当前页面唯一主行动；
- 白底描边：次行动、可撤销行动；
- 纯文字：返回、取消和低优先级入口；
- 同一区域有两个同权操作时都使用描边按钮，不人为制造错误主次；
- 等待期间禁用重复提交，并提供可见进度；
- 只有高风险或不可逆操作使用红色危险态，并在执行前二次确认；退出登录等可恢复操作使用中性描边样式。

### 12.6 底部导航

- 固定为“发现／连接／协作／我的”四项；
- 图标与文字同时展示，文字不得小于 11px；
- 蓝色只标记当前 Tab 和未处理数量；
- “碰卡”是跨页面的线下事件，不作为第五个 Tab；
- 导航与手机手势区之间必须包含安全区，页面内容不能永久被遮挡。

### 12.7 COSPAN Space 手机伴随端

- 手机只展示项目状态、启动进度、需要我确认的分工、我的任务、关键动态和 SOS；
- 首屏只有一个清晰主行动，例如“查看并确认分工”；
- 复杂权限、完整任务编排和贡献记录在电脑端展开；
- 飞书和 GitHub 承担日常执行，COSPAN 不复制聊天、文档和代码管理。

### 12.8 开屏动画

- 动画叙事固定为：两人靠近／碰卡 → COSPAN Space 轮廓形成 → 中英文 Slogan → COSPAN 品牌；
- 中文固定为“人与人先相遇，人与 Agent 再共创。”，英文固定为“Meet as people. Build with agents.”；
- Slogan 必须位于 Room 轮廓内部，不与边框、人物或底部品牌重叠；
- 默认约 2.4 秒自动退出，用户点击任意位置可跳过；
- 开启“减少动态效果”时直接展示终态，并约 0.9 秒退出；
- 小高度设备必须缩放构图或调整位置，不能裁切文字；
- 开屏退出后必须移除，不能继续遮挡页面或拦截点击；
- 自动化浏览器默认跳过开屏，可用显式参数单独验收。

### 12.9 设置入口与设置面板

- “我的”左上角显示 44×44px 圆形设置图标，具有可见边界、轻阴影和 `aria-label`；
- Hover 可轻微上移或旋转，触屏仍需有按压反馈；
- 设置通过底部面板打开，不替换“我的”主内容；
- 面板至少包括动效／声效、设备与隐私、数据与授权、展会与账号；
- 默认最小公开原则在设置中持续可见；
- 退出登录归为中性低频账号操作，不使用红色；删除账号、永久清除数据等危险操作与普通设置行分区展示，并使用危险态和二次确认。

### 12.10 底部面板与浮层

- 详情、筛选、设置和编辑优先使用底部面板；
- 面板底部包含安全区，拖拽区域本身至少 44px；
- 预览态与全屏展开态的边界清楚；
- 点遮罩可以关闭，但存在未保存内容时必须确认；
- 焦点、滚动和返回键不能穿透到后方页面。

### 12.11 外部平台与协作证据

“我的”中的外部平台属于用户授权的协作证据，不是后台偷偷抓取资料。

- 支持 GitHub、小红书、即刻、LinkedIn、抖音、作品链接和其他公开链接；
- 用户主动粘贴 HTTPS 公开主页或作品地址；
- GitHub 可以读取并展示公开摘要，例如用户名、公开仓库数和关注者；
- 其他平台默认只保存用户主动提交的地址，不读取私信、草稿或非公开内容；
- 输入行由平台标识、单行地址和明确保存操作组成，保存操作至少 44px 可触达；
- 已连接和未连接状态必须清楚，但不为每一行增加厚重卡片外框；
- 首次公开“能力证据”或“外部平台链接”时，说明已有同字段内容也会公开，并要求确认；
- 用户暂停展示或撤回字段授权后，推荐、附近、名册和 NFC／QR 公开页立即停止展示；
- 注册流程不强制连接外部平台，链接补充失败也不能阻断进入产品。

### 12.12 COSPAN Block

- 作品／项目证据支持链接、标题、文字、图片、Demo 和 App；
- 经历支持高光、教育、工作和获奖；社交平台支持 GitHub、X、小红书、即刻和更多；
- 每项内容先预览，再由用户明确授权公开；
- 只展示真实、可追问的证据，不生成虚构履历；
- 没有证据时使用轻量空状态和“添加内容”，不显示羞辱性完成度评分。

## 13. 手机、电脑与硬件展示屏的视觉关系

三个终端共享品牌名、黑白灰基调、蓝色行动语义、状态文案和协作身份，但信息密度不同：

| 终端 | 主要任务 | 视觉策略 |
|---|---|---|
| 手机 | 发现、建联、现场确认和协作伴随 | 14px 正文、单列卡片、44px 触控 |
| 电脑 | COSPAN Space 项目启动与治理 | 多栏信息、完整变更与贡献记录 |
| ESP32-8048S043 竖向工牌 | 对外展示自己的最小状态并触发碰卡 | 480×800 / 3:5 竖屏、彩色状态反馈、极少字段 |

手机中只展示面板旋转 90° 后、按比例缩小的 `480×800` 竖向工牌预览，因此其内部允许出现小于 10px 的模拟字号；真实硬件 UI 必须在 ESP32-8048S043 实机上按物理尺寸、观看距离和触控范围单独验收。

## 14. 页面级规范

### 14.1 发现

- 默认主演示入口是“推荐”；推荐一次聚焦一人，可连续浏览全部候选，不使用前端 `slice` 静默截断；
- “附近”只有在页面前台且用户公开状态开启时才启动定位；
- 离开附近、锁屏、暂停公开或关闭应用时立即停止定位并撤销旧心跳；
- 其他人只能看到距离分桶，不能看到经纬度；
- 特殊展会开启名册时，名册与推荐、附近共享人物详情和授权数据；
- 筛选条件决定候选“是否出现”，AI 只解释排序；0 人时显示空状态，不自动放宽。

### 14.2 连接

- 清楚区分想认识、待回应和已建联；
- 展示相遇来源，例如线上请求、NFC／QR 或双方碰卡；
- 连接是长期关系，不等于某个项目成员；
- 已建联但方向未定时，主行动是“开始意图澄清”，不是直接分配任务；
- 已有项目邀请与新建项目流程分开，不能重复创建项目。

### 14.3 协作

- 没有项目时展示邀请和清晰空状态；
- 有方向草案但未确认时展示三字段澄清与双方确认状态；
- 有项目后展示启动进度、成员、一个下一步行动、我的任务和关键动态；
- Agent 建议使用“建议、理由、风险、待确认”，不呈现为已生效命令；
- 手机视图减少卡片外框，使用分区、留白和分割线；
- 宽屏视图可展开成员、建议与记录三栏，但不加入聊天和通用项目管理。

### 14.4 我的

从上到下的建议顺序：

1. 随页面滚动的品牌区与左上角圆形设置按钮；
2. 身份摘要；
3. 当前公开状态和时效；
4. 对外协作卡／COSPAN Block；
5. 墨水屏公开面预览；
6. 外部平台连接；
7. 能力与项目证据；
8. 低频账号操作。

“我的”不增加固定或吸顶顶栏。设备、隐私、授权和账号管理等低频功能统一进入设置面板，避免主页面层级过长；“退出当前账号”不是账号管理或不可逆危险操作，可作为页面末尾唯一的低频会话操作保留，并使用中性描边样式。

## 15. 内容、状态与反馈

### 15.1 文案语气

- 短、直接、以用户行动为中心；
- AI 使用“建议、可能、待确认”，不使用“最佳、一定、已决定”等绝对措辞；
- 不把人称为“高分候选人”，不公开人才排名；
- 主按钮描述结果，例如“想认识”“确认方向”“查看并确认分工”，避免笼统“确定”；
- 隐私文案说明谁能看、看什么、看到何时，以及如何撤回。

### 15.2 通用状态

每个异步或数据模块至少具备：初始／空状态、加载状态、成功回执、网络失败与重试、权限拒绝、会话过期、无结果、已暂停／已撤回和重复提交保护。

Live 模式失败不能回退到静态假数据伪装成功。Toast 不能是唯一反馈，关键结果需保留在页面状态中。

### 15.3 动效、声音与触控反馈

- 页面切换、卡片拖动、底部面板和状态变更使用 160–320ms 的短动效；
- 开屏可以使用完整叙事动效，但必须可跳过；
- 左右滑动可使用不同方向声纹，用户可在设置中关闭；
- 不能依赖动画、震动或声音才能理解结果；
- Hover 是桌面增强反馈，不能成为手机端唯一反馈。

## 16. 无障碍、内容与隐私

- 关键文字与背景对比度目标为 WCAG AA；
- 不只用红绿或明暗表达状态，必须保留文字或图标；
- 按钮提供可理解的名称，图标按钮必须有 `aria-label`；
- 进度条、切换、Tab 和展开状态提供正确语义；
- 系统字体放大后关键流程仍可操作，不通过裁切隐藏正文；
- 动态提示不得遮挡持续操作，Toast 需要自动消失且不能是唯一反馈；
- 用户能力、项目与“为什么推荐”属于授权内容，不把未授权资料混入活动名册；
- AI 文案使用“建议、可能、待确认”，不使用未经证实的绝对判断；
- 默认最小公开，并逐字段授权；展会授权绑定具体命名活动和有效期；
- 位置只在“附近”前台运行，NFC／QR 落地页只展示有限公开字段；
- 外部平台只处理公开链接和用户明确提交的内容；
- 公开范围变更、暂停和撤回必须即时生效；
- 用户可以查看当前公开范围、删除资料、退出账号和撤销会话；
- 不把未授权资料混入推荐、Agent 上下文或公开证据。

## 18. 每次界面改动的交付流程

每一次影响手机端的改动都必须完成：

1. 运行浏览器 Smoke Test；
2. 对受影响页面做 390×844 截图回归；
3. 运行相关 Live E2E 或后端测试；
4. 构建 Android APK；
5. 安装到已连接手机；
6. 在真机检查字号、触控、滚动、安全区、卡片底部和开屏；
7. 记录已验证设备与发现的问题。

Android 构建和安装以 `android-app/README.md` 的当前命令为准。进入生产开发前，还需补充 Android 动态字体、iOS 安全区、深色模式、键盘导航和真实设备对比度测试。
