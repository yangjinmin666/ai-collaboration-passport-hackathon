# RALLY｜集结：移动端视觉与字体规范

> 版本：v1.0  
> 日期：2026-08-29  
> 状态：96 小时 Demo 基线已应用  
> 适用范围：RALLY 手机端、新手引导、建联流程与手机端 RALLY Room

## 1. 设计目标

RALLY 的手机端服务于黑客松、展会和线下协作现场。用户需要在移动、交谈和时间压力下快速完成浏览、建联与确认，因此视觉系统优先保证：

1. 一屏只突出一个主要判断或行动；
2. 正文在真机上可直接阅读，不使用被缩小的设计稿字号；
3. 黑白灰承担信息层级，蓝色只表示行动、选择和实时信号；
4. 人物、能力证据和项目状态比装饰更醒目；
5. 手机、电脑 RALLY Room 与墨水屏属于同一产品，但不复制彼此的信息密度。

## 2. 品牌颜色

### 2.1 基础 Token

| Token | 色值 | 用途 |
|---|---:|---|
| `--paper` | `#F7F8FA` | 页面浅灰白底色 |
| `--white` | `#FFFFFF` | 卡片、浮层和选中 Tab |
| `--ink` | `#17212D` | 标题、正文和主要图标 |
| `--muted` | `#6F7B89` | 次要说明、时间和元信息 |
| `--line` | `#D6DDE7` | 边框、分割线和未激活轮廓 |
| `--cobalt` / `--guide-blue` | `#347CF8` | 主要按钮、选中状态和关键实时信号 |
| `--cobalt-deep` | `#245FC8` | 蓝色文字与高对比交互态 |
| `--signal` | `#EAF2FF` | 蓝色状态的浅色背景 |
| `--guide-blue-soft` | `#F0F5FF` | 引导说明和轻量提示背景 |

### 2.2 使用规则

- 页面不使用大面积蓝色底或装饰性渐变；
- 一个视区原则上只保留一个实心蓝色主行动；
- 蓝色不代表“匹配分高”，只代表可行动、已选择、进行中或需要关注；
- 成功、警告和错误在进入生产版后应增加独立语义色，不能长期都借用品牌蓝；
- 普通正文优先使用 `--ink`，辅助文字使用 `--muted`，不要用低透明度文字代替明确色值。

## 3. 字体系统

### 3.1 字体栈

```css
font-family: "SF Pro Display", "PingFang SC", "Helvetica Neue", Arial, sans-serif;
```

中文以苹方为真机基准，数字和英文沿用系统无衬线字体。编号、时间戳、微标签和墨水屏状态可使用等宽字体，但不用于长段正文。

### 3.2 字号与行高

| 层级 | Token | 字号 | 建议行高 | 典型用途 |
|---|---|---:|---:|---|
| 展示标题 | `--type-display` | 28px | 1.15 | 人名、核心结果 |
| 页面标题 | `--type-page-title` | 24px | 1.3 | 名册、RALLY Room 项目名 |
| 分区标题 | `--type-section-title` | 18px | 1.3 | 模块标题、人物详情标题 |
| 卡片标题 | `--type-card-title` | 16px | 1.3–1.4 | 状态、任务和证据标题 |
| 正文 | `--type-body` | 14px | 1.5 | 推荐理由、说明和关键内容 |
| 标签／辅助 | `--type-label` | 12px | 1.4–1.5 | 标签、时间、按钮辅助信息 |
| 英文微标签 | `--type-micro` | 10px | 1.4 | Eyebrow、编号和少量元数据 |

### 3.3 强制规则

- 手机端普通可见文字不得小于 10px；
- 连续阅读正文从 14px 起，不用 10–12px 承载完整句子；
- 12px 只用于标签、时间和单行辅助信息；
- 10px 只用于短英文微标签、编号和低权重元数据；
- 标题最多两级同时出现，避免同屏出现过多粗体；
- 中文正文默认行高 1.5，长句不得使用紧行高；
- 省略号只用于可以点开查看完整内容的区域。

## 4. 间距与布局

RALLY 使用 8px 基础节奏，并保留 4px 处理图标、标签和紧密元素之间的微间距。

| Token | 数值 | 用途 |
|---|---:|---|
| `--space-1` | 4px | 图标与文字、标签内部微间距 |
| `--space-2` | 8px | 同组元素间距 |
| `--space-3` | 12px | 卡片内部紧凑间距 |
| `--space-4` | 16px | 页面左右边距、标准卡片内边距 |
| `--space-5` | 24px | 分区间距 |
| `--space-6` | 32px | 大模块或流程阶段间距 |

布局规则：

- 390px 基准视口使用 18px 左右页面边距，生产版可收敛为 16px Token；
- 主要卡片内容距边缘不少于 16px；
- 底部导航为悬浮层时，页面必须预留至少 96px 的底部滚动空间；
- 推荐页一次聚焦一位候选人；附近与名册承担全局浏览，不把推荐页压成表格；
- 不允许页面产生横向滚动。

## 5. 圆角、边框与阴影

| 层级 | 圆角 | 使用范围 |
|---|---:|---|
| 大容器 | 30px | 推荐主卡、核心结果卡 |
| 标准卡片 | 22px | 模块卡、浮层、RALLY Room 卡片 |
| 控件 | 16px | 按钮、输入区、分段控件 |
| 胶囊 | 999px | 状态、标签、头像 |

- 默认边框为 1px `--line`；
- 阴影只用于悬浮导航、主推荐卡和浮层，普通列表不用阴影堆层级；
- 阴影不能替代边框，浅灰白页面上仍需保持卡片轮廓；
- 人物头像一律为正圆，素材使用居中裁切，不露出灰色底边。

## 6. 触控与反馈

- 主要交互目标的包围盒不得小于 44×44px；横向按钮可以更宽，但高度仍不得小于 44px；
- 底部导航单项高度不低于 56px；
- 推荐卡的“暂不看／看详情／想认识”需要同时提供图形和文字，不能只靠颜色区分；
- 点击、选中、等待和完成必须有可见反馈；
- 焦点态使用 3px 蓝色轮廓，并与控件保持 3px 间距；
- 附近雷达中的头像是空间可视化例外，可低于 44px，但选中后应在下方生成标准尺寸的操作卡，不能要求用户只点极小头像完成关键操作；
- 尊重系统的减少动态效果设置，核心流程不能依赖动画才能理解。

## 7. 核心组件规范

### 7.1 顶部品牌区

- 左侧只展示 `RALLY` 与当前一级模块；
- 右侧活动胶囊只显示当前活动和必要状态，不承担附近雷达开关；
- 品牌区不使用大面积品牌色。

### 7.2 分段控件

- 用于同一模块内的并列视图，如“推荐／附近／名册”和“启动／分工／动态”；
- 高度至少 44px；
- 未选中项使用灰字，选中项使用白底和蓝色文字；
- 不同时使用底线、实心背景和投影表达同一选中状态。

### 7.3 人物推荐卡

- 首屏依次回答：对方状态、身份、能力标签、证据、推荐理由；
- 不显示标准化匹配百分比；
- AI 输出用“为什么建议认识”解释，不伪装为客观评分；
- 卡片正面只放快速决策信息，完整经历进入详情浮层；
- 左滑表示“暂时略过”，右滑表示“想认识”，都不等于正式建联。

### 7.4 状态标签

- 文案必须能独立表达含义，颜色只作为强化；
- 主状态与实时信号分开：如“团队补位中”是主状态，“项目 SOS”是实时信号；
- 标签默认 12px；空间极紧时可使用 10px，但不得承载长句。

### 7.5 按钮

- 实心蓝色：当前页面唯一主行动；
- 白底描边：次行动、可撤销行动；
- 纯文字：返回、取消和低优先级入口；
- 同一区域有两个同权操作时都使用描边按钮，不人为制造错误主次；
- 危险操作进入生产版后必须使用独立危险态和二次确认。

### 7.6 底部导航

- 固定为“发现／连接／协作／我的”四项；
- 图标与文字同时展示，文字不得小于 11px；
- 蓝色只标记当前 Tab 和未处理数量；
- “碰卡”是跨页面的线下事件，不作为第五个 Tab。

### 7.7 RALLY Room 手机伴随端

- 手机只展示项目状态、启动进度、需要我确认的分工、我的任务、关键动态和 SOS；
- 首屏只有一个清晰主行动，例如“查看并确认分工”；
- 复杂权限、完整任务编排和贡献记录在电脑端展开；
- 飞书和 GitHub 承担日常执行，RALLY 不复制聊天、文档和代码管理。

## 8. 手机、电脑与墨水屏的视觉关系

三个终端共享品牌名、黑白灰基调、蓝色行动语义、状态文案和协作身份，但信息密度不同：

| 终端 | 主要任务 | 视觉策略 |
|---|---|---|
| 手机 | 发现、建联、现场确认和协作伴随 | 14px 正文、单列卡片、44px 触控 |
| 电脑 | RALLY Room 项目启动与治理 | 多栏信息、完整变更与贡献记录 |
| 墨水屏工牌 | 对外展示自己的最小状态并触发碰卡 | 高对比、低刷新、极少字段、无复杂交互 |

手机中的墨水屏只是按比例缩放的设备预览，因此其内部允许出现小于 10px 的模拟字号；这些字号不能复制到真实手机 UI。量产墨水屏仍需按照实际尺寸、观看距离和屏幕分辨率单独验收。

## 9. 无障碍与内容规则

- 关键文字与背景对比度目标为 WCAG AA；
- 不只用红绿或明暗表达状态，必须保留文字或图标；
- 按钮提供可理解的名称，图标按钮必须有 `aria-label`；
- 动态提示不得遮挡持续操作，Toast 需要自动消失且不能是唯一反馈；
- 用户能力、项目与“为什么推荐”属于授权内容，不把未授权资料混入活动名册；
- AI 文案使用“建议、可能、待确认”，不使用未经证实的绝对判断。

## 10. 工程映射与验收

当前 Token 和手机端覆盖规则位于：

- [prototype/mobile-demo/styles.css](./prototype/mobile-demo/styles.css)
- [prototype/mobile-demo/smoke_test.py](./prototype/mobile-demo/smoke_test.py)

自动验收基线：

1. 390×844 视口无横向溢出；
2. 推荐、附近、名册和手机 RALLY Room 的普通可见文字不小于 10px；
3. 除附近雷达头像等明确例外外，普通按钮和控件触控尺寸不小于 44px；
4. 墨水屏缩略预览不参与手机字号断言；
5. 四项底部导航、11 位角色和完整建联—入队—分工闭环保持可用。

运行：

```bash
cd prototype/mobile-demo
python3 smoke_test.py
```

进入生产开发前，还需补充 Android 动态字体、iOS 安全区、深色模式、键盘导航和真实设备对比度测试。
